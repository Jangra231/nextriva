Staged Next.js Migration Prompts

Centralised Two-Account Portal with Working Capabilities
Use these prompts one stage at a time with your AI coding assistant. Do not give all stages
in one message. Complete the acceptance checklist for one stage, commit the changes, and
only then start the next stage.
The goal is to migrate the existing Next.js website from separate user types and user IDs to
two account types while keeping the existing workflows working.
   Important: The CSR workflow must not be simplified away. An approved CSR capability
   must be fully operational and must allow the User to submit new sponsorship requests,
   receive Administrator review, receive an Administrator-assigned event, view only that
   assigned event, view limited participant data, track funding and impact, and repeat the
   process for additional events with separate approval each time.

Final target model
The application must contain only these account types:

The former MCD, MCD/BMC, or BMC capability must be renamed to Local Authority in the
interface, database, API, route names, permissions, reports, seed data, and documentation.
Preserve legacy values through a safe migration mapping.

Rules for every stage
1. Inspect the existing code before modifying it.
2. Do not delete or rename existing production tables without a migration and rollback
   plan.
3. Do not remove existing routes until replacement routes are tested.
4. Keep a compatibility layer while old and new models coexist.
5. Use feature flags where a change could affect existing users.
6. Use database transactions for multi-record changes.
7. Never trust capability, function, or scope values sent by the browser.
8. Enforce permissions in the backend as well as in the UI.
9. Add tests before enabling a migrated feature for all users.
10.At the end of every stage, report changed files, database changes, tests run, known
   issues, and rollback steps.

How to use this guide
Start with Stage 0. Give only one stage prompt to the coding assistant at a time. Ask it to
stop after the stage’s acceptance checklist and provide its change summary. Review the
result, run the tests, commit the changes, and then continue to the next stage.
If the coding assistant cannot complete a selected function end to end, do not activate that
function. Keep it unchecked until its complete implementation is ready.
